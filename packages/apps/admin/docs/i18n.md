# Internationalization (i18n) Guidelines

## Overview

This document outlines the internationalization strategy for the Admin Dashboard.

## Supported Languages

### Current

- English (en-US) - Default
- Japanese (ja-JP)

### Planned

- Spanish (es-ES)
- French (fr-FR)
- German (de-DE)

## Implementation

### Framework

Using Next.js built-in i18n support with `next-intl`:

```typescript
// app/[locale]/layout.tsx
import {NextIntlClientProvider} from 'next-intl';
import {getMessages} from 'next-intl/server';

export default async function LocaleLayout({
  children,
  params: {locale}
}: {
  children: React.ReactNode;
  params: {locale: string};
}) {
  const messages = await getMessages();

  return (
    <NextIntlClientProvider messages={messages}>
      {children}
    </NextIntlClientProvider>
  );
}
```

## Translation Keys

### Naming Convention

Use hierarchical, descriptive keys:

```json
{
  "users": {
    "title": "Users",
    "table": {
      "headers": {
        "name": "Name",
        "email": "Email",
        "status": "Status"
      },
      "actions": {
        "edit": "Edit",
        "delete": "Delete",
        "view": "View Details"
      }
    },
    "form": {
      "labels": {
        "name": "Full Name",
        "email": "Email Address"
      },
      "placeholders": {
        "name": "Enter user's name",
        "email": "user@example.com"
      },
      "validation": {
        "nameRequired": "Name is required",
        "emailInvalid": "Invalid email format"
      }
    }
  }
}
```

### Usage in Components

```typescript
import {useTranslations} from 'next-intl';

export default function UserTable() {
  const t = useTranslations('users.table');

  return (
    <table>
      <thead>
        <tr>
          <th>{t('headers.name')}</th>
          <th>{t('headers.email')}</th>
          <th>{t('headers.status')}</th>
        </tr>
      </thead>
    </table>
  );
}
```

## RTL Support

### CSS Considerations

```css
/* Use logical properties */
.container {
  margin-inline-start: 16px; /* Instead of margin-left */
  padding-inline-end: 8px; /* Instead of padding-right */
  text-align: start; /* Instead of text-align: left */
}
```

### Component Adjustments

```typescript
import {useLocale} from 'next-intl';

function Layout({children}: {children: React.ReactNode}) {
  const locale = useLocale();
  const isRTL = ['ar', 'he', 'fa'].includes(locale);

  return (
    <div dir={isRTL ? 'rtl' : 'ltr'}>
      {children}
    </div>
  );
}
```

## Best Practices

### Do's

- ✅ Externalize all user-facing text
- ✅ Use semantic keys that describe content
- ✅ Include context for translators
- ✅ Test with longest translations
- ✅ Use formatters for dates/numbers
- ✅ Consider text expansion (30% for some languages)

### Don'ts

- ❌ Hardcode text in components
- ❌ Concatenate translated strings
- ❌ Use technical keys (e.g., `btn_1`)
- ❌ Assume text direction
- ❌ Embed HTML in translations

## Translation Process

### Workflow

1. **Development**: Developers add keys in English
2. **Extraction**: Extract new/changed keys
3. **Translation**: Send to translation service
4. **Review**: Native speakers review
5. **Integration**: Import translations
6. **Testing**: QA in each language

### Tools

```bash
# Extract translation keys
bun run i18n:extract

# Validate translations
bun run i18n:validate

# Check for missing keys
bun run i18n:missing
```

## Language Detection

### Priority Order

1. User preference (stored in profile)
2. URL parameter (`?lang=ja`)
3. Browser language
4. Default language (en-US)

### Implementation

```typescript
import { match } from '@formatjs/intl-localematcher';
import Negotiator from 'negotiator';

export function getLocale(request: Request): string {
  const negotiatorHeaders: Record<string, string> = {};
  request.headers.forEach((value, key) => {
    negotiatorHeaders[key] = value;
  });

  const languages = new Negotiator({ headers: negotiatorHeaders }).languages();
  const locales = ['en-US', 'ja-JP'];
  const defaultLocale = 'en-US';

  return match(languages, locales, defaultLocale);
}
```

## Testing

### Unit Tests

```typescript
describe('i18n', () => {
  it('should display correct translation', () => {
    const {getByText} = render(
      <NextIntlClientProvider locale="ja-JP" messages={messages}>
        <Component />
      </NextIntlClientProvider>
    );

    expect(getByText('ユーザー')).toBeInTheDocument();
  });
});
```

### E2E Tests

```typescript

  await page.goto('/');

  await expect(page.locator('h1')).toContainText('ダッシュボード');
});
```
